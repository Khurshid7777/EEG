# BDSP: что сделать владельцу, чтобы сессия получила данные (по вашему согласию на использование ваших AWS-ключей)

Согласие владельца проекта на использование **его собственных AWS-ключей только для чтения данных BDSP** получено 2026-11-27. Ключи я не вижу и не принимаю в чате; они задаются в настройках окружения. Служебные переменные `AWS_*` песочницы не ваши и не используются — для ваших ключей нужны **другие имена** (ниже).

## 1. Аккаунты и соглашения (вы)

1. Зарегистрируйтесь на https://bdsp.io (Register), подтвердите email.
2. На страницах ресурсов нажмите «Request access» / подпишите соглашение (DUA). Без аккредитации доступны **restricted**-наборы: SPaRCNet https://bdsp.io/content/bdsp-sparcnet/1.1/ , I-CARE https://bdsp.io/content/bdsp-icare/2.0/ , Burst Suppression https://bdsp.io/content/bsupp/1.0/ , Cyclops https://bdsp.io/content/cyclops/2.0/ , SpikeNet 2.0 https://bdsp.io/content/spikenet2/1.0/ , TEEGLLTEEG https://bdsp.io/content/teegllteeg/1.2/ . Открытые наборы (https://bdsp.io/content/dhypothermia/1.0/ и др.) подписи не требуют.
3. Для доступа к S3 BDSP просит ID вашего AWS-аккаунта (форма на странице ресурса, раздел «Files → Click here to request access»): укажите его — BDSP свяжет аккаунт с одобренными наборами.

## 2. Ключи AWS (вы) — только чтение

1. В консоли AWS создайте **отдельного IAM-пользователя** (например, `neurolens-bdsp-readonly`), без доступа к консоли, с политикой:
```json
{"Version":"2012-10-17","Statement":[{"Effect":"Allow","Action":["s3:GetObject","s3:ListBucket"],
 "Resource":["arn:aws:s3:us-east-1:184438910517:accesspoint/*","arn:aws:s3:us-east-1:184438910517:accesspoint/*/object/*"]}]}
```
   (Для вызова `sts:GetCallerIdentity` права не нужны.)
2. Создайте для него ключ доступа (Access key). Сохраните только в менеджере паролей и в настройках окружения.
3. В настройках окружения этого проекта добавьте **переменные окружения** (не network secrets: подпись AWS считается на стороне клиента, прокси подставить её не может):
   * `BDSP_AWS_ACCESS_KEY_ID`
   * `BDSP_AWS_SECRET_ACCESS_KEY`
4. Начните **новую сессию** (в текущей переменные не появятся).

**О рисках.** Переменные окружения хранятся в настройках в открытом виде и видны людям с доступом к окружению: поэтому нужен отдельный read-only пользователь без других прав, а после работы ключ следует удалить или ротировать. Ключи не вставляйте в чат и в репозиторий.

## 3. Что сделаю я в новой сессии

* `python scripts/bdsp_s3.py check` — проверка личности и открытой точки доступа; листинг одобренных наборов (`ls ARN`), скачивание только нужных файлов.
* Читаю описание набора и **до открытия данных** пишу пре-регистрацию (метки, критерии, разбиение), коммитлю, затем открываю данные.
* Порядок: SPaRCNet (периодические паттерны: калибровка LPD/BIPD, слабый случай инкремента 83), затем IED-наборы (Cyclops, SpikeNet), Burst Suppression, I-CARE v2.0.
* Использую данные только по условиям соглашений (без передачи третьим лицам, без реидентификации); производные числа — в репозиторий, сырые данные — нет (`data/` в `.gitignore`).

## 4. Если что-то не получается

`check` покажет, какой шаг не пройден (ключи не заданы / ключ не привязан к аккаунту BDSP / набор ещё не одобрен). Скажите, какая ошибка, и я подскажу, что исправить.
