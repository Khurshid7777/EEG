# Пре-регистрация инкремента 49: стадирование сна на стандартном монтаже ПСГ AASM (OpenNeuro ds005555, BOAS)

Зафиксировано до запуска на тестовых данных. Скрипт проверки — `scripts/run_boas_sleep.py`,
разработка — `scripts/dev_aasm_stager.py`.

## Зачем

Стадировщик продукта работает с производными Fpz-Cz/Pz-Oz (средняя линия) или Fp2-C4/P4-O2
(инкремент 14). Стандартный монтаж клинической ПСГ по AASM — F4, C4, O2 (и F3, C3, O1) против
сосцевидного отростка, без Fp, Cz, Pz и P4. Такую запись продукт сейчас **не стадирует вовсе**:
`derivations` возвращает None. Это самый распространённый монтаж в лабораториях сна.

## Разработка (только CAP Sleep Database, все 96 записей с полной цепочкой)

Производные: F4-C4 и C4-O2 (в CAP — сумма C4-P4 и P4-O2), ЭОГ ROC-LOC; левая цепочка, если нет
правой. Кросс-валидация по пациентам (5 фолдов), `docs/increment49_dev_cv.json`:

| Модель на производных AASM | Каппа |
|---|---|
| Sleep-EDF v1 без дообучения | 0.552 |
| клиническая v1 (инкремент 14) без дообучения, 67 ночей вне её обучения | 0.670 |
| новая, обучена на производных AASM (CV) | **0.717** |

Финальная модель обучена на всех 96 ночах: `configs/models/sleep_stager_aasm_v1.json`,
SHA-256 `fab0f2b3dea88586b75141e3f0c9d2e1725d460cf5bf53e7a932356ea509022e`.

В код добавлено (по умолчанию выключено, `configs/sleep.yaml` не меняется до решения):
* `sleep.aasm_model` — стадировщик для монтажа F4-C4 / C4-O2; используется, только если нет ни
  средней линии, ни парасагиттальной цепочки Fp2-C4/P4-O2;
* ЭОГ из двух референциальных глазных электродов (EOGR/EOGL, ROC/LOC) — их разность;
* префикс `PSG_` в именах каналов.

## Тестовые данные

OpenNeuro ds005555 (BOAS; Bitbrain, Сарагоса; CC0): 128 ночей у 100 взрослых без тяжёлых
неврологических болезней, ПСГ Micromed 256 Гц, F3/F4/C3/C4/O1/O2 против M1, ЭОГ, ЭМГ. Разметка —
консенсус трёх экспертов по AASM для каждой 30-с эпохи (`stage_hum`; код 8 — отключение ПСГ,
исключается). Ранее из набора открывались: описание, README, `participants.tsv`, перечень файлов
и `channels.tsv`, `eeg.json` и первые 5 строк `events.tsv` sub-1 (проверка формата). Сигналы не
открывались.

## Метод (как в продукте)

* Каждая ночь читается конвейером, возраст из `participants.tsv`; стадирование —
  `Pipeline._sleep_staging` с `aasm_model` = замороженная модель. Порогов и правил не меняется.
* Сравнение по эпохам: стадия продукта для эпохи k (с начала записи) против консенсуса экспертов,
  все эпохи с меткой экспертов (W, N1, N2, N3, REM).
* Ночи, которые не читаются или не стадируются, перечисляются и исключаются; сбой загрузки
  повторяется один раз.

## Метрики

* Каппа Коэна по всем эпохам (5 классов); 95% ДИ — бутстреп по людям (`pid`; 2000 повторов,
  seed 49), так как часть людей записана дважды.
* Точность, macro-F1, F1 по стадиям, медиана каппы по ночам.
* Справочно (не гипотеза): согласие автоматической разметки авторов (`stage_ai`) с консенсусом.

## Гипотеза и правило решения

* **H1:** каппа ≥ 0.60 и нижняя граница ДИ ≥ 0.50.
* Выполнена → `aasm_model` включается в `configs/sleep.yaml`: записи с монтажом AASM
  стадируются.
* Не выполнена → остаётся выключенным; отрицательный результат сообщается.

## Известные ограничения

* Здоровые взрослые (без пациентов), один центр, один прибор.
* Модель обучена на CAP (Италия, пациенты с нарушениями сна): перенос и на центр, и на популяцию.
