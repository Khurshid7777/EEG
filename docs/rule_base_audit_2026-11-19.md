# Аудит базы правил `configs/rules/neuro_rules.yaml` (2026-11-19)

Цель: для каждой цепочки «паттерн → причина → вывод» выписать утверждение, источник, ограничения, что **код реально проверяет**,
и чем это можно проверить. Это основа для рецензии невролога-нейрофизиолога; **сам по себе документ ничего не валидирует**.

## Как читать

* **Источник** — литература, на которую опирается утверждение. Ссылки даны по моим знаниям, **без сверки с первоисточником
  (страницы, DOI не проверены)**; помечены «(сверить)». Это отправная точка для рецензента, а не подтверждение.
* **Что делает код** — по чтению `rules_engine.py`, `periodic.py`, `special.py`, `physiology.py`. Условие срабатывания
  всех цепочек — только присутствие события (`any_event`); `context_present/absent` в файле не используется ни одной цепочкой.
* **Статус:** A — формулировка соответствует логике кода; B — формулировка сильнее логики кода (код не проверяет то, что утверждает текст);
  C — правило не может сработать.

## Найденные расхождения (главное)

| 1 | `triphasic_metabolic` | **B** | Текст: «на фоне печёночной/почечной недостаточности». Код: срабатывает на любое событие `triphasic_waves`, контекст (`hepatic/renal`) не проверяется. Трифазные волны **неспецифичны** (описаны и при других причинах: гипоксия, токсические, септическая энцефалопатия; визуально похожи на GPD) — вывод «метаболическая энцефалопатия» без контекста слишком сильный. ## Общее

* **Уверенности (`confidence`)** 0.5–0.8 заданы вручную и не откалиброваны ни на каких данных; их нельзя читать как вероятности.
* **Условия по контексту** (`context_present/absent`) поддержаны движком, но **ни одно правило их не использует**: это самый дешёвый способ
  исправить расхождения 1, 3, 5, 6 без нового кода.
* Возрастные границы правил не заданы (кроме неонатальных, где вход — ПМВ).

## Пробелы: что отсутствует (кандидаты, без источников — для рецензии)

Генерализованные спайк-волны 3 Гц (абсансы), гипсаритмия, фотопароксизмальный ответ, периодические острые комплексы при
прионных болезнях, альфа-кома/веретенная кома, низкоамплитудная ЭЭГ/электроцеребральное молчание (вне задач системы),
бета-активность от бензодиазепинов/барбитуратов (физиологический эффект препаратов), доброкачественные варианты помимо викета (мю, лямбда, POSTS,
BETS/SSS, 14&6, RMTD), нормальные неонатальные паттерны (delta brush, tracé alternant/discontinu). Какие добавлять — решает рецензент.

## Что предлагается сделать (по порядку, ничего не включено в продукт этим документом)

1. **Рецензия невролога:** подтвердить или исправить цепочки 1–14 и сверить источники.
2. **Исправления формулировок без изменения логики:** слабые выводы (ВЧД, HIE, «острый структурный процесс») переписать как вероятности с дифференциалом; в текстах
   не утверждать контекст, которого код не проверяет.
3. **Использовать `context_present/absent`:** трифазные волны → метаболическая энцефалопатия только при указанной печёночной/почечной
   недостаточности; без контекста — «неспецифично, дифференциал»; вспышка-подавление без контекста — не «приоритет тяжёлого
   повреждения», а «контекст не указан».
4. **Гейтинг delta brush по возрасту/ПМВ** (код и метка физиологии) — после рецензии.
5. **Проверка на данных** там, где есть метки причины: I-CARE (кома после остановки сердца, исходы), клинические отчёты NMT-4K после доступа;
   каждое правило включается только после пре-регистрированной проверки.
6. **Мёртвое правило (№11):** либо реализовать распознавание сонливости/замедления при активации, либо удалить цепочку.
