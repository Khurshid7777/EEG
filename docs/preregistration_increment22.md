# Пре-регистрация, инкремент 22: оценка аномальности уровня записи

> Зафиксировано и опубликовано **до** запуска пайплайна на оценочной части NMT
> (`docs/increment22_eval_ids.json`); записи на диск не загружались.

## 1. Что предлагается

Правила заключения решают «отклонения» по **одной** находке (кандидат-спайк с оценкой обученной
модели ≥ 0.95, замедление при медленном ЗДР, …). Инкремент 21 показал, что решающая информация —
не морфология кандидата, а оценки обученных моделей и фон. Модель уровня записи
(`layer5_reasoning/record_model.py`) взвешивает **вместе** то, что пайплайн уже вычисляет:
возраст, ЗДР, относительные мощности, амплитуду, распределение оценок обученной модели разрядов,
число/длительность/оценку событий модели приступов, долю дельты+теты, какие находки сработали и
какие признаны патологическими (41 признак). Градиентный бустинг (глубина 3, 300 деревьев,
шаг 0.05, L2 1.0 — заданы до обучения), JSON, инференс на numpy.

**Обучение:** все 1 045 ранее использованных записей NMT (720 нормальных, 325 аномальных;
`docs/increment20_dev.json`, `docs/increment20_metrics_new.json` — выходы текущего пайплайна).
**Порог** — заранее заданная специфичность 0.75 на предсказаниях вне фолда (5-кратная
стратифицированная CV): **0.229** (`docs/increment22_cv.json`).

| На 1 045 записях (вне фолда) | Специфичность | Чувствительность | Сбаланс. точность |
|---|---|---|---|
| правила (инкремент 20) | 0.728 | 0.723 | 0.725 |
| модель уровня записи, порог 0.229 | 0.750 | **0.828** | **0.789** |
| AUC модели | | | 0.869 |

Признаки в пайплайне и при обучении считаются одной функцией (`pipeline/record_summary.py`);
совпадение проверено на записях разработки.

## 2. Проверка — оценочная часть NMT (повторное использование, оговорено)

Аномальные записи обучающей части NMT исчерпаны; NMT-4K-EEG — с ограниченным доступом.
Проверка — на **оценочной части авторов NMT** (95 нормальных, 90 аномальных; конфликты меток
исключены). Она уже была тестом **один раз** (инкремент 17, пайплайн того времени) и с тех пор
не использовалась ни для разработки, ни для настройки: правила 18–21 и модель уровня записи на
ней не видели ни одной записи. Это второе использование — слабее первой проверки, что и сказано
здесь заранее.

Сравнение — в **одном прогоне** пайплайна этого коммита: заключение модели (оценка ≥ 0.229)
против заключения правил (`rule_impression_abnormal`) на тех же записях.

## 3. Гипотезы (`evaluation/prereg22.py`)

* **H1** — сбалансированная точность модели выше, чем у правил, не менее чем на **0.03**
  (на разработке +0.064).
* **H2** — специфичность модели ≥ **0.65**.
* **H3** — чувствительность модели не ниже, чем у правил, более чем на **0.03**.

## 4. Правило решения (`prereg22.apply_decision`)

* **H1 ∧ H2 ∧ H3** → `configs/impression.yaml: record_model_decides: true`: заключение
  «норма/отклонения» решает оценка записи, находки правил перечисляются для просмотра; числа в
  `impression.yaml` — специфичность и чувствительность модели на оценочной части.
* Иначе → `record_model_decides: false`: оценка только сохраняется в JSON-результате, заключение
  решают правила, числа инкремента 20 остаются.

## 5. Воспроизведение

```bash
PYTHONPATH=src python scripts/train_record_model.py configs/models/record_gbm_v1.json docs/increment22_cv.json docs/increment20_dev.json docs/increment20_metrics_new.json
PYTHONPATH=src python scripts/prefetch_nmt.py docs/increment22_eval_ids.json --threads 10
PYTHONPATH=src python scripts/run_routine_ids.py docs/increment22_eval_ids.json docs/increment22_eval.json data/nmt 4
```

## 6. Ограничения

* Модель обучена на метках одной группы неврологов одного центра (NMT); перенос на другие центры
  не проверен — оценочная часть того же центра.
* Модель наследует признаки текущего пайплайна: любое изменение детекторов меняет её входы и
  требует переобучения и новой проверки.
* Метка — на уровне записи; модель не локализует и не называет патологию — это остаётся за
  находками правил, которые перечисляются в заключении.
