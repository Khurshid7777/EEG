# Пре-регистрация инкремента 55: сглаживание гипнограммы по переходам между стадиями (монтаж AASM)

Зафиксировано до запуска на тестовых данных. Разработка — `scripts/dev_sleep_smoothing.py`, проверка —
`scripts/run_cinc2018_smoothing.py`.

## Зачем

Стадировщик решает каждую эпоху отдельно; контекст соседних эпох входит только в признаки. Человек-эксперт
не меняет стадию каждые 30 с: у модели на примере tr03-0083 стадия меняется на 16.7% эпох, у экспертов —
заметно реже. Идея: выбрать наиболее вероятную последовательность стадий (алгоритм Витерби) с учётом
вероятностей переходов, измеренных на размеченных ночах. Стадировщик (v4) не меняется.

## Разработка (четыре центра, исключение одного центра)

Вероятности фолд-моделей v4 (обучены на трёх других центрах); матрица переходов фолда — только по
обучающим центрам. Каппа по центрам, `docs/increment55_dev_smoothing.json`:

| Вес переходов | ds007181 | BOAS | EESM19 | HMC | Среднее |
|---|---|---|---|---|---|
| 0 (без сглаживания) | 0.610 | 0.541 | 0.675 | 0.613 | 0.610 |
| 0.25 | 0.628 | 0.559 | 0.685 | 0.620 | 0.623 |
| **0.5** | 0.634 | 0.568 | 0.686 | 0.618 | **0.627** |
| 1.0 | 0.636 | 0.578 | 0.684 | 0.609 | 0.627 |
| 1.5 | 0.635 | 0.585 | 0.679 | 0.600 | 0.625 |

Выбран вес 0.5: максимум среднего (делит его с 1.0), прибавка на всех четырёх центрах, меньше риск
перегладить (на HMC вес 1.0 и выше уже вредит). Прибавка на HMC мала (+0.005).
Параметры заморожены: `configs/models/sleep_smoothing_aasm_v1.json` (вес 0.5, матрица переходов по всем
416 ночам разработки), SHA-256 `be614d1c8c95709734df5bb14d396c08fbd88eff98713f853f4f2fb7841a851f`.
Стадировщик — v4, SHA-256 `3affd3b5bb9c996f56259fe85817065ddc6ee4fbe29a57fd3a81f985e7b102d7`.
Вес выбирался по тем же четырём центрам, на которых оценивался, поэтому оценка на разработке
оптимистична — тест на новой выборке именно для этого.

В продукте сглаживание — только на пути AASM; остальные пути не меняются.

## Тест: новая случайная выборка PhysioNet/CinC Challenge 2018

Тот же центр (MGH), что в инкременте 52, но 150 других записей: из 993 обучающих записей исключены 150
записей инкремента 52 и tr03-0005; выборка случайная (seed 53), пересечение с прежней — 0 записей.
Для всех записей — одна гонка пайплайна, из которой берутся две гипнограммы (сглаженная и обычный
argmax тех же вероятностей), поэтому сравнение парное.

* Из новой выборки открывался только перечень `RECORDS` (для выбора). Сигналы и разметки этих записей
  не открывались. Работа кода проверена на записи tr03-0083 из выборки инкремента 52 (каппа 0.745 → 0.767;
  смен стадии на эпоху 16.7% → 5.6%).
* **Основная метрика:** разность каппы (сглаженная минус обычная) по всем эпохам всех записей; 95% ДИ —
  парный бутстреп по записям (2000, seed 53).
* Справочно: каппа и F1 по стадиям в обоих вариантах, доля смен стадии на эпоху.

## Гипотезы и правило решения

* **H1:** прибавка каппы ≥ +0.005 и нижняя граница парного ДИ > 0.
* **Предохранитель:** ни одна стадия не теряет по F1 более 0.03 (сглаживание не должно «съедать» редкие
  стадии: N1, N3).
* H1 выполнена и предохранитель цел → `sleep.aasm_smoothing` = `sleep_smoothing_aasm_v1.json` в
  `configs/sleep.yaml`.
* Иначе — остаётся выключенным; результат сообщается.
* Ничего на тесте не подбирается. Записи, которые не читаются или не стадируются, перечисляются и
  исключаются; сбой загрузки повторяется один раз.

## Ожидание

По разработке прибавка около +0.01 (на HMC +0.005) — то есть около порога H1. Исход не предрешён.

## Известные ограничения

* Тот же центр, что в инкременте 52: это проверка сглаживания, а не переноса на новый центр.
* Матрица переходов собрана по четырём центрам в целом; у людей с нарушениями сна (апноэ, частые
  пробуждения) переходы иные, и сглаживание может скрывать фрагментацию сна — клинически значимую
  находку. Это ограничение войдёт в текст отчёта при включении.
