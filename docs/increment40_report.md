# Инкремент 40: признаки формы разряда и поля (модель разрядов v3) — отрицательный результат разработки

Только обучающая часть NMT-Events (184 записи: 64 с разрядами, 120 нормальных), перекрёстная
проверка с теми же фолдами и бюджетом 15 ложных/ч, что в инкременте 15
(`scripts/dev_ied_v3.py`, `docs/increment40_dev.json`). Тестовые наборы не открывались.

## Что добавлено (критерии IFCN, которых не было в v1)

У канала с наибольшей крутизной в каждом окне 0.5 с: ширина доминирующего пика на половине
высоты (спайк 20–70 мс, острая волна 70–200 мс), асимметрия подъёма и спада, полярность
(поверхностно-негативный пик), поле — число и доля соседних электродов 10-20 с не менее
половины относительной амплитуды (`layer4_detect/ied_ml.py`: `peak_morphology`, `field_counts`).

## Результат

| | признаки v1 | v3 |
|---|---|---|
| AUC окон (вне фолда) | 0.940 | 0.943 |
| чувствительность при 15 ложных/ч | 0.639 | 0.634 |
| ложных/ч на нормальных записях | 12.8 | 12.4 |
| нормальных записей хотя бы с одним обнаружением | 50 из 120 | 45 из 120 |

Прогон на признаках v1 точно воспроизводит замороженную рабочую точку инкремента 15
(0.639 / 12.80) — конвейер тот же.

## Решение

Прирост (+0.003 AUC) не стоит повторного использования тестовых наборов: v3 **не замораживается и
не проверяется**; рабочей остаётся v1. Признаки остаются в коде (вычисляются, но v1 их не
использует; ~1.4 с на 14 мин записи) для воспроизводимости.

Почему, вероятно: признаки v1 уже несут почти ту же информацию — острота и крутизна относительно
фона задают длительность, «следующее окно 1–4 Гц» — последующую медленную волну, число каналов
выше 3×/5× фона — поле. Слабость в бодрствовании (AUC 0.72 на vepiset) на NMT-Events не видна:
там нет меток состояния; для неё нужны обучающие данные с бодрствованием/сном и артефактами.
