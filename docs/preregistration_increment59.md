# Пре-регистрация инкремента 59: заключение «норма / отклонения» на оценочной части NMT-4K

Зафиксировано **до получения доступа к данным**: набор закрытый (Zenodo 21405022, «restricted»), содержимое файлов
не открывалось. Использовано только публичное описание записи. Метод тот же, что в инкрементах 56–58.

## Зачем

Чувствительность заключения вне оценочной части NMT не измерена (находка F1 аудита, инкремент 56): все патологические
записи NMT уже использованы. NMT-4K — единственный известный набор, где есть свежие патологические рутинные ЭЭГ с
заключением невролога. Он же даёт специфичность на ещё одной свежей выборке.

## Данные

NMT-4K-EEG (Zenodo 21405022, опубликован 2026-09-13): 4 500 рутинных ЭЭГ 4 500 пациентов двух больниц Пакистана,
19 каналов, 200 Гц, EDF, заключение «норма / патология» по проверке невролога, возраст, пол, больница в
`metadata/recordings.tsv`. **Тест — только оценочная часть (split = evaluation): 540 нормальных и 460 патологических
записей, ранее не публиковавшихся, без пересечения пациентов с обучающей частью.** Обучающая часть (3 500) в тесте не
участвует. Экспертные метки событий (1 164 патологических записи) в этом инкременте не используются.

**Что известно заранее и может повлиять:** NMT-4K, вероятнее всего, от той же группы, что и NMT; одна из двух больниц
может совпадать с центром NMT. Поэтому результат читается как «новые записи тех же или родственных центров», а не как
чужая больница; разбивка по больницам обязательна. Обучающая часть NMT-4K может содержать записи NMT — на тест это не
влияет, потому что используется только оценочная часть, но пересечение оценочной части с NMT проверяется: запись
исключается и перечисляется, если пара «возраст, пол, длительность» совпадает с записью NMT (`Labels.csv`) и совпадает
SHA-256 EDF с ранее скачанным файлом NMT.

## Что запускается

Текущая рабочая конфигурация без изменений (`run_record`, `scale=1.0` после проверки единиц на двух отведённых
записях вне теста; возраст из `recordings.tsv`). Скачивание по одной записи и удаление (диск мал).

## Метрики

Чувствительность и специфичность итогового заключения; точные 95% ДИ Клоппера–Пирсона; AUC вероятности модели записи
(бутстреп по записям, 2000, seed 59). Описательно: по больницам, по возрасту (< 2, 2–11, 12–17, 18–59, ≥ 60), только
правила / только модель, доля пограничных, чувствительность по группам событий (по `label` и, где доступны, по
семейству событий отчёта).

## Гипотезы и правила решения

* **H1 (AUC):** ≥ 0.85 (на оценочной части NMT было 0.897; ожидается небольшое снижение).
* **H2 (специфичность):** ≥ 0.72 («подтверждено»); 0.65–0.72 «ниже цели»; < 0.65 «не выдержало».
* **H3 (чувствительность):** ≥ 0.70 «подтверждено»; 0.55–0.70 «ниже цели»; < 0.55 «не выдержало».
* **Решение для продукта:**
  * H2 и H3 не «не выдержало» → `routine_validated` остаётся; в конфигурацию добавляется число чувствительности этого
    теста (и обновляется число специфичности), текст отчёта показывает оба как «оценка на не использовавшихся
    записях», с пометкой «ниже цели» там, где она есть.
  * Любой из H2/H3 «не выдержало» → `routine_validated: false`: заключение «норма / отклонения» считается
    непроверенным, текст отчёта сообщает об этом (режим B закрыт).
  * AUC < 0.80 → разбор причин (калибровка по больницам, единицы, возраст) без подгонки порогов к этим данным.
* Порогов, возрастных поправок и модели по оценочной части не подбирать. Если потребуется перекалибровка, она
  делается на обучающей части NMT-4K отдельным инкрементом с новой пре-регистрацией и повторным тестом на других записях.

**Ожидание.** AUC 0.85–0.90; специфичность 0.70–0.76; чувствительность 0.65–0.80 (прежние оценки 0.80 были подобраны на
оценочной части NMT, а на свежих 345 записях правила давали 0.60). Я не уверен, что H3 подтвердится.

**Исключения.** Запись, которая не читается, исключается и перечисляется; сбой загрузки повторяется один раз.

## Ограничения

* «Патологическая» — заключение невролога по рутинной ЭЭГ, а не клинический исход.
* Возможное родство с центром NMT: тест не полностью независим по центру.
* Доступ зависит от решения владельцев набора; без него инкремент не запускается.
