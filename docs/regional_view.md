# Региональная карта коры + процесс диагностики на одном экране (инкременты 73–76)

## Что это

Один интерактивный экран (самодостаточный HTML, без внешних библиотек и сети) и страница PDF-отчёта, где **одновременно** показаны:
1. **процесс диагностики по времени** — события детекторов (спайки, иктальные паттерны, замедление и др.), стадии сна (если есть), окна с артефактами, региональные полосы (10 строк: 5 областей × левое/правое полушарие);
2. **региональная карта коры** выбранного окна — скальповая карта (интерполяция по электродам или ячейки «доля × полушарие»), межполушарная асимметрия с нормативным коридором, текстовая подпись и список событий с областями.

Как пользоваться: клик/перетаскивание по таймлайну, стрелки ←/→, ползунок или «Воспроизвести»; диапазон (дельта/тета/альфа/бета); показатель (относительная мощность или отклонение z от медианы записи); «Вся запись» — среднее по окнам без артефактов; «Закрепить A» — фиксирует окно A, карта показывает разность B − A (сравнение двух состояний/моментов); RU/UZ.

## Где получить

* Из пайплайна: `Pipeline.save_outputs` создаёт `regional_view.html`, `regional_static.png` и страницу в `report.pdf`; `result.json` содержит блок `regional` (средние по областям, асимметрия с флагами, события по областям).
* Для одного файла: `PYTHONPATH=src python scripts/make_regional_view.py INPUT.edf OUT.html`.
* Примеры на открытых данных (только производные мощности, не сигнал): `docs/demo/regional_eegmat_rest.html`, `regional_eegmat_task.html` (здоровый доброволец, покой и счёт), `regional_siena_seizure.html` (фрагмент вокруг приступа; страница не указывает сторону очага). Пересборка: `scripts/make_regional_demo.py`. Заключение на странице — вывод обычного пайплайна на фрагменте, не клиническая оценка пациента.

## Что проверено (пре-регистрации и решения)

| Инкремент | Вопрос | Итог |
|---|---|---|
| 73 (D113) | затылочно-теменной максимум альфа; эффект счёта; симметрия | максимум альфа сзади — 92–93% (ДИ 0.77–0.99), эффект счёта (лобная тета ↑ у 67%, задняя альфа ↓ у 81%) подтверждены; жёсткий порог симметрии 0.20 — нет |
| 74 (D114) | нормативные пределы асимметрии | по парам переносятся между центрами (доля вне пределов 0.07, максимум 0.12); флаг «любая пара» даёт 35% ложных — не используется |
| 79 (D119) | топография ритмов сна на HMC (151 ночь) | пре-регистрированная метрика (относительная мощность) **не подтвердила**: веретёна 55%, дельта 83%, альфа бодрствования 87% |
| 80 (D120) | то же по абсолютной (log10) мощности на BOAS (128 ночей, один референт) | **подтверждено**: веретёна N2 центр > затылок 93.6% (ДИ 0.88–0.97), лобная дельта N3 > затылочной 98.3% (n = 58) |
| 77–78 (D117–D118) | привязка события к каналу/области по сигналу | полушарие 0.79/0.875, но область не добрала критерий → не включено |
| 75 (D115) | сторона начала приступа (Siena, 13 пациентов) | **не подтверждена** (сбалансированная точность 0.51, p = 0.087) → сторона очага не заявляется |

## Записи сна и редкие монтажи

Для записей со стадиями сна (и вообще для монтажей с менее чем 8 стандартными электродами, например ПСГ F4/C4/C3/O2 или F3/F4/C3/C4/O1/O2) страница работает с референтом записи (без общего среднего): показываются области по имеющимся электродам, диапазон «сигма (веретёна)» и показатель «абсолютная мощность (log10)» — он выбирается по умолчанию, т. к. только он подтверждён для сна (D119, D120). Относительная мощность для сна помечается предупреждением. Нормативный коридор асимметрии (получен для общего среднего) не применяется. Заключение рутинной ЭЭГ для записи сна на странице заменено пояснением (его правила рассчитаны на бодрствование). Пример: `docs/demo/regional_hmc_sleep.html`.

## Что намеренно **не** делается (и почему)

* **Источниковая локализация** (sLORETA и т. п.) — 19 электродов дают слишком низкое пространственное разрешение; требует ≥ 32 электродов, шаблона головы и отдельной проверки.
* **Сторона/доля очага** — не подтверждена на данных (D115).
* **Флаг «патологическая асимметрия» по одной или любой паре** — ложных меток у здоровых слишком много (D114); показывается число и нормативный коридор по паре; коридор применим к записи целиком, в окне — ориентир.
* **Привязка события к области по каналам** — только если детектор указал каналы (у части детекторов каналов нет — на странице «без привязки к каналам»); локализацию события по сигналу сам экран не выдумывает.
* **«Функция коры»** — не измеряется; вместо этого — наблюдаемые ритмы по областям. Литературные интерпретации (например, задняя альфа при закрытых глазах = покой зрительной коры) пока не выводятся на экран, т. к. сверка цитат заблокирована (eutils закрыт).

## Рассмотренные варианты оформления

| Решение | Выбрано | Почему / что не выбрано |
|---|---|---|
| Тип карты | оба: интерполяция по электродам **и** ячейки «доли × полушария» | интерполяция привычна, но создаёт ложную «гладкость» между электродами; ячейки точно соответствуют определениям областей из инкремента 73 |
| Показатель | относительная мощность и z от медианы записи | абсолютная мощность не показана: зависит от импеданса и усиления; сравнивать окна внутри записи надёжнее по z |
| Сравнение | закрепление A и разность B − A | сравнение двух записей — через существующий `neurolens compare`; здесь — два момента одной записи |
| Асимметрия | значение записи (ромб) против коридора + значение окна (кружок, ориентир) | флаг только на уровне записи: коридор получен на минутных записях |
| Артефакты | окно серое, значения помечены ненадёжными | сегментация артефактов продукта (инкремент 61) не прошла проверку и не подключена |
| Формат | один HTML-файл, без CDN | работает офлайн в клинике; данные внутри файла, сеть не нужна |
| Язык | RU/UZ | подписи и вывод; заключение берётся из текста отчёта |

## Ограничения

Скальповое картирование: 19 электродов 10-20 (доли и полушария), общий средний референт, окна 4–120 с; монтажи без достаточного числа стандартных электродов (< 8; например, неонатальные) — блок `regional` помечается как недоступный; для записей длиннее 2 ч анализируется представительный фрагмент каждого окна (до 30 с); сигнал после предобработки продукта (пре-регистрированные проверки считались на исходных записях с общим средним референтом — небольшие отличия возможны). Страница не диагностирует и не заменяет врача.
